This release adds an explicit path from a browser download to a local workspace. Download a generated file normally, select it under **Browser files → workspace**, share it with one connected conversation, and approve the import. Images, PDFs, ZIPs and other formats keep their original bytes.

New `list_artifacts` and `import_artifact` tools expose only user-selected files. Imports stream up to 64 MiB, preserve the original, refuse overwrites, recheck hashes and permissions after approval, and keep receipts in SQLite and the audit chain. Grants are scoped to a session and workspace, expire after 24 hours, and can be revoked before import. Signed download URLs and private source paths are never sent to the model.

Local verification passed 91 workspace tests and 41 host self-tests. In Chrome, Kimi generated an SVG, its normal download control saved it, a denied import left no file, and an approved model-requested import produced an identical 311-byte workspace copy. The import result and subsequent read-back returned to the conversation with the same SHA-256.

Reload the extension and provider tabs after installation. Chrome's card, the panel and the host must show **0.5.0**, protocol **5**. This adds Chrome's Downloads permission; macOS may also request Downloads access for the rebuilt host. Follow [the browser-files guide](https://github.com/mrfentmen/unified-ai-bridge/blob/main/docs/BROWSER-FILES.md) and [build/install guide](https://github.com/mrfentmen/unified-ai-bridge/blob/main/packaging/DEPLOY.md).

This first step requires explicit selection. It does not automatically discover or download provider artifacts, upload local files to chats, unpack archives, execute imported code, understand media, or provide large-binary undo. Existing text recovery limits remain unchanged. Other providers' artifact flows and a physical Intel Mac remain unverified; [the verification record](https://github.com/mrfentmen/unified-ai-bridge/blob/main/docs/VERIFICATION.md) preserves earlier evidence and limitations.
