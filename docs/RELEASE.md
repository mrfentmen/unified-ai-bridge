This release adds ZIP inspection, approved creation from selected workspace files, and approved extraction into a new folder. Entry lists and hashes appear before approval. Traversal, symlinks, filename collisions, protected paths and oversized archives are rejected; extraction validates CRCs and publishes its destination only after every entry succeeds. Contents are never executed.

Local verification passed **121 workspace tests** and **41 installed self-tests**. In Chrome, the extension created a 734-byte ZIP from existing Rust, Markdown and Kimi-generated SVG files, extracted all three byte-for-byte, and denied another extraction without creating its destination. The Chrome card, shadow panel and host agree on **0.5.5**, protocol **6**.

This is a bounded ZIP32/Stored/Deflate subset: up to 256 entries, 32 MiB compressed, 16 MiB per file, 64 MiB expanded and depth 12. ZIP64, encrypted/ambiguous archives, recursive nested extraction and large-binary undo are not supported. See [archive controls](https://github.com/mrfentmen/unified-ai-bridge/blob/main/docs/ARCHIVES.md) for all limits and interruption handling.

Reload the extension and provider tabs after installation. These live checks exercise panel controls, not a new model conversation loop. Persistent macOS consent across unsigned rebuilds, the full current-build provider matrix and a physical older Intel Mac remain unverified.
