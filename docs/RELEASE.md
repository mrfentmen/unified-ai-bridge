0.5.26 adds generated-file discovery and approved downloads to the browser bridge. A model or the panel can discover rendered ChatGPT file cards and explicit download links, then request a download using a short-lived handle. The host checks ownership, applies task budgets, requests approval and records the attempt before any browser action. A timeout or restart cannot silently download the same file again.

ChatGPT file buttons still need an explicit sharing step: Chrome exposes the site origin, not the originating conversation. The bridge returns `manual_share_required` instead of guessing from filenames or download times. Supported direct links use Chrome’s returned download ID; that path is implemented and covered by automated transport/policy tests, but its real-provider acceptance remains open.

Live ChatGPT evidence includes discovery returned to the model, stale-task refusal, approval denial and an approved 283-byte SVG download. The installed host then imported that actual download through an explicitly approved native framing harness; source and destination hashes match. Browser selection → import → conversation delivery was interrupted when the verification tabs changed. Older cards can also disappear through website virtualization and need to be brought into view. These are named gaps, not an unattended pass.

The panel’s file selectors now retain the selected value across status refreshes and clear disconnected sessions. Source, package, Chrome card, panel and native hello agree on 0.5.26 / protocol 9. Validation passed 261 workspace tests, 41 installed-host self-tests and documentation tests; one long-running test remains intentionally ignored. Doctor verified SQLite and 1,089 matching audit entries at its recorded snapshot. Detailed evidence is in [VERIFICATION.md](VERIFICATION.md).

Uploads, image delivery to models, other providers’ generated-file adapters, broader application control and fully unattended coordination remain unfinished. Existing filesystem, coding, document, media and approved-command tools remain available. macOS permission persistence still needs a stable user-supplied signing identity and OS grants; physical older Intel testing remains separate from CI.
