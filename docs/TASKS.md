## Shipping gates for every task

- Add or update the catalog/schema, profile availability, instructions, panel controls, permission decisions, audit events, and output limits together. Reject unknown tool arguments and model-supplied identity.
- Exercise a meaningful allow case, denial, malformed/stale input, and relevant interruption/race cases. Use real temporary files and real UI/provider evidence where applicable; fixtures do not establish an integration.
- Preserve traversal/symlink protection, immutable research datasets, explicit deletion approval and trash, and the ban on arbitrary shell. The archaeology project is not a test directory.
- Keep long outputs bounded with continuation cursors. Do not advertise image/document/media support from metadata alone.
- Verify source/package/loaded-build agreement before browser acceptance. Repeat the affected provider matrix; name blocked or unsupported behavior instead of counting it as a pass.
- Run Linux/Intel macOS CI where supported. A physical Intel Mac and the minimum supported macOS/Chrome combination remain separate release checks; do not add architecture-specific or newer-OS dependencies without making that requirement explicit.

The first delivery group is **UAB-01–07**: stable permissions, readiness, bounded grants, durable jobs, provider reliability, controls/reporting and long commands. Next prioritize **UAB-08, UAB-11–14 and UAB-16–18** for useful coding and file workflows. The remaining entries are staged extensions, not commitments to ship every format or application at once.
