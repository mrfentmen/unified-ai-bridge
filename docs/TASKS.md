# Next implementation tasks

This is the actionable backlog after 0.5.0, updated November 16, 2026. Boxes are checked only when their stated acceptance conditions have passed; remaining boxes are **open**. Tool names are proposals until their schemas and behavior are implemented and tested. Adding a task does not grant OS permissions, enable an integration, authorize uploads, or schedule unattended execution.

Current capabilities come from `crates/bridge-core/src/catalog.rs`; live evidence belongs in [VERIFICATION.md](VERIFICATION.md). Ordinary file editing, append/copy/trash/restore, batch reads, glob/tree/diff, Git status/diff, approved commands, native MCP discovery/calls, and selected-download imports already exist. Extend them where indicated instead of creating duplicate tools.

## 1. Make unattended work dependable

Start here. The current configuration permits 16 calls per task, 4 per assistant response, 180 seconds for an approval, and 240 seconds for a tool call. These are current limits, not recommended overnight defaults. The installed host has an ad-hoc linker signature; stable signing and permission persistence still need implementation and verification.

- [ ] **UAB-01 — Stable host installation and macOS permissions.** Establish a consistent signing identity and installation path; document the one-time Files & Folders/Accessibility/Automation grants actually needed. Keep credentials out of the repository. Do not rebuild or reload the host during an active job. **Done when:** two consecutive updates retain the intended identity, required file access works without recurring prompts in a real Chrome session, and any remaining authentication requirement is named. Do not promise unattended permission dialogs or lock-screen access.
- [ ] **UAB-02 — Readiness check and machine/workspace information.** Add read-only `system_info` and `workspace_info`, plus a panel preflight showing the loaded builds, active root, profile, command grants, free disk, relevant permissions, connected tabs, and adapter readiness. Report uncertain OS grants as unknown until exercised. Offer an explicit, time-bounded keep-awake option for a job. **Done when:** a missing host, wrong build, locked workspace, missing command, or unready browser produces a specific readiness result; ending the job releases any power assertion.
- [ ] **UAB-03 — Scoped overnight permissions.** Let the user grant named operations in a specific workspace/session for a stated duration, with file/byte/call budgets and immediate revocation. Preserve research dataset and cross-agent denials. Keep deletes, uploads, downloads from new sources, external processes, and desktop input as separately chosen capabilities. Models cannot create or enlarge grants; generic Trusted mode is not blanket overnight consent. **Done when:** a selected allowed task completes without repeated approval, while an ungranted path/tool, expired grant, changed file, and revoked grant each stop correctly and leave audit evidence. Depends on UAB-02.
- [ ] **UAB-04 — Durable jobs and safe recovery.** Store job ownership, workspace, steps, budgets, receipts and blocked reasons in SQLite. Add `list_jobs` and `job_status`; user controls start, pause, and resume. Restore known results after reconnect; mark uncertain mutations for reconciliation rather than executing them again. A queued job must not invent a new user task or silently switch provider/conversation. **Done when:** closing/reopening Chrome or killing/restarting the host preserves job status and does not duplicate a write. Workspace changes leave running steps bound to their original root.
- [ ] **UAB-05 — Provider and background-tab reliability.** Exercise every current adapter, including both Grok URLs, on a verified loaded build. Handle hidden/virtualized messages, streaming, candidate-answer selection, busy composers, and user drafts. Where foreground rendering is required, show the limitation and use focus automation only when the user has enabled it. **Done when:** each supported flow has real connect/read/create/result/navigation/background evidence, or a named blocked/unverified result. Login, CAPTCHA and account limits pause the job for user action; they are never bypassed.
- [ ] **UAB-06 — Job controls, budgets and completion report.** Add progress, current step, elapsed time, blocked reason, remaining budgets, Pause/Stop, and a local completion report linking changed files, results and audit receipts. Budgets are selected before a job; reaching one must not trigger automatic escalation. **Done when:** Stop prevents new work, interrupted work has an explicit outcome, and the report distinguishes completed, failed, cancelled and unverified steps. Depends on UAB-03–05. Scheduled starts come only after these recovery tests pass and require a user-created schedule.

## 2. Finish the coding workflow

- [ ] **UAB-07 — Long-running commands and process visibility.** Extend `run_command` to support host-owned job IDs, bounded output cursors, `read_job_output`, and `cancel_job`. Add bounded `inspect_processes` starting with bridge-owned processes; it must not expose secrets from command arguments or environments. Preserve exact executable/argument grants, wall-time limits, process-tree cleanup and normal non-zero exit results. **Done when:** a real build/test runs past the current foreground-call limit, output can be resumed without duplication, cancellation stops descendants, and a non-allowlisted invocation is denied. Depends on UAB-03–04. No arbitrary shell or interpreter loophole.
- [x] **UAB-08 — Changes across several files.** Add `preview_patch`, `apply_patch`, and `restore_patch`, with a bounded structured list of operations and expected hashes for existing files. Show all affected paths and differences before approval, record per-file recovery receipts, and report partial application honestly. **Done when:** a real multi-file edit is previewed/applied/restored, stale files and symlink escapes are rejected, and an injected mid-operation failure leaves an accurate recoverable record. Do not claim filesystem-wide atomicity.
- [ ] **UAB-09 — Code navigation and diagnostics.** Extend text search with bounded line-numbered code matches; add `list_symbols` and `find_references` where a verified Rust-native parser or explicitly configured native language server supports them. Link build/test diagnostics back to files and lines. **Done when:** a code task locates a symbol, updates its callers using UAB-08, and runs a granted check; unsupported languages clearly fall back to text search rather than invented semantic results.
- [ ] **UAB-10 — Reviewed Git changes.** Extend the existing Git tools/command presets with log/show and a user-authorized branch/commit workflow. Show the actual diff and exact file list; preserve unrelated user modifications. **Done when:** a disposable dirty repository keeps its unrelated edits, the approved files are committed, and a failed operation is reported. Push, merge, destructive reset/clean and credential handling are not silently included in a local commit grant.

## 3. Move generated files between chat and computer

- [ ] **UAB-11 — Approved local-file uploads.** Add `attach_file_to_chat` using a selected file, explicit outbound-sharing grant, fixed target conversation, size/type checks, and an expected content hash. Recheck the file before sending; local read permission alone does not grant upload permission. **Done when:** a real local file appears as a completed attachment in the intended provider chat, a rejected upload sends nothing, and failed/uncertain uploads are not blindly repeated. Document supported providers individually. Depends on UAB-03 and UAB-05.
- [ ] **UAB-12 — Discover and download visible chat outputs.** Add `list_generated_files` and `request_download` for visible artifacts in a granted tab/current conversation turn. Cover images, code bundles, documents, spreadsheets, slides, audio/video and canvases only where the website provides them. Use short-lived handles and ordinary UI download actions; correlate the resulting Chrome download before reusing the existing artifact importer. **Done when:** a real provider output is discovered, downloaded and imported with matching bytes and correct conversation attribution; a changed turn, stale handle, ambiguous download, missing original, or unavailable website feature returns a clear outcome. No hidden endpoints or signed URLs in model results.
- [ ] **UAB-13 — Let the model see images and screenshots.** Connect existing screenshot capture and local image selection to UAB-11. Show an approved preview and bounded dimensions, then verify actual image attachment completion. **Done when:** the intended image reaches the conversation and a genuine visual task uses it; returning a local filename is not counted as visual delivery. Keep observation permissions distinct from permission to send the image to an AI website.
- [x] **UAB-14 — Safe archive handling.** Add `list_archive`, `extract_archive`, and `create_archive`, starting with ZIP. Preview entries; cap count, expanded bytes and nesting; reject traversal, absolute paths, symlinks and collisions. Extraction writes into a new approved folder and never executes contents. **Done when:** a real project bundle round-trips, an unsafe archive cannot write outside the root, and a failed extraction reports/removes only its own incomplete output.
- [ ] **UAB-15 — Recovery for larger binary files.** Extend the change journal beyond the current 1 MiB text-recovery limit with bounded private file snapshots, hashes, disk-space checks, retention settings and explicit cleanup controls. Reuse `list_changes`/`restore_change` rather than introducing a second recovery interface. **Done when:** a permitted larger file can be replaced, trashed and restored byte-for-byte without overwriting later edits or silently exhausting storage. This must pass before format editors replace existing large files.

## 4. Understand and edit common file formats

- [ ] **UAB-16 — Read PDF and Word documents.** Add bounded `extract_document_text`, `document_info`, and `render_document_pages`, starting with declared PDF/DOCX subsets. Preserve page references, report truncation/continuation, and distinguish embedded text from scanned pages. OCR is a separate optional capability with an explicit availability result. **Done when:** text extraction and rendered-page inspection succeed on real documents, encrypted/unsupported inputs produce honest errors, and malicious external references or document macros are not followed/executed. Prefer Rust libraries; any external native helper requires compatibility and grant checks.
- [x] **UAB-17 — Image inspection and transformations.** Add `image_info` and `transform_image` with an explicit operation enum for resize, crop, rotate and supported format conversion. Bound decoded dimensions/memory; write to a new path by default. These are deterministic file operations; visual understanding comes through UAB-13. **Done when:** a real image is transformed, reopened and checked for expected dimensions/format, with oversized/corrupt files and protected destinations rejected. Raster image generation continues through a supported website's own UI, not a new provider API.
- [ ] **UAB-18 — Tables and spreadsheets.** Add `read_table`/`query_table` for bounded CSV/TSV rows, columns, filters and aggregations; use structured filters, not arbitrary SQL or scripts. Add `inspect_workbook`, `read_sheet_range`, and `write_sheet_range` for a tested XLSX subset. Explicitly report formula evaluation, cached-value and formatting limitations. **Done when:** a real table/workbook is read, edited and reopened with expected cells, stale-hash protection, preserved supported content, and denied writes covered. Do not silently flatten unsupported workbook features. Depends on UAB-15 for replacing larger files.
- [ ] **UAB-19 — Produce documents and presentations.** Start with `create_document`/`export_document` for structured content into tested DOCX/PDF outputs, then add `create_presentation` for a small declared PPTX feature set. Use fixed schemas and named templates. **Done when:** outputs open in real viewers, rendered pages/slides are inspected, and overwrites, unsupported features and broken exports are handled explicitly. Arbitrary rich editing is a later format-specific task, not implied by successful export. Depends on UAB-16; replacement workflows also need UAB-15.
- [ ] **UAB-20 — Audio/video inspection and conversion.** Add `media_info` first, followed by explicit bounded operations such as trim, audio extraction or thumbnails where a reviewed native implementation is available. Do not accept free-form media-tool arguments. **Done when:** sample outputs are playable and metadata/duration match the requested operation, with time/disk limits enforced. Transcription, narration and generation require a separately verified local capability or supported website workflow; saving media alone does not establish those features. Depends on UAB-07 and UAB-15 for long/replacement operations.

## 5. Inspect running projects and work in applications

- [ ] **UAB-21 — Policy-gated web text and downloads.** Add `fetch_url_text` and `download_file`; keep network access off by default. Permit reviewed HTTP(S) requests with bounded redirects/time/bytes, recheck destinations after DNS resolution/redirects, and deny private/loopback targets unless separately granted. Never borrow browser cookies or auth headers; keep URL secrets out of logs. **Done when:** public text can be fetched and a file downloaded into an approved destination, while disabled access, private-network redirects, oversized bodies and disallowed writes are denied. Authenticated chat downloads continue through UAB-12 and Chrome.
- [ ] **UAB-22 — Browser verification of a running project.** Add `browser_snapshot`, `browser_screenshot`, and scoped `browser_action` for a user-selected preview tab: inspect visible text/accessibility state, click, type, scroll, and read bounded console errors. Start development servers only through approved commands. A separately granted local preview URL is not a replacement transport for Native Messaging. **Done when:** the bridge edits a small app, runs it, performs a real UI check and reports evidence. Actions cannot spill into unrelated tabs, arbitrary page script execution, private browser storage, or credential extraction. Depends on UAB-05, UAB-07 and UAB-13.
- [ ] **UAB-23 — Targeted desktop input.** Extend existing app/window inspection with `focus_application`, `click_element`, `type_text`, `press_keys`, and `scroll_window` using Rust/native accessibility bindings and host-issued target handles. Revalidate focus and targets before each action; provide separate input permission, a visible activity record and an immediate Stop control. **Done when:** a disposable app task succeeds and focus changes, stale handles, missing Accessibility permission and Stop all prevent misdirected input. No model-supplied AppleScript or arbitrary OS commands. Depends on UAB-03, UAB-06 and UAB-13.
- [ ] **UAB-24 — Finish native MCP integration operations.** Extend existing `list_integrations`/`call_integration_tool` with `integration_status`, bounded progress/results, cancellation, schema-change reapproval and clear server health. Test actual application servers one at a time when the workflow needs them; ordinary filesystem work does not need a separate integration per app. **Done when:** a real configured native server survives disconnect/reconnect without cross-talk or duplicate mutations, image results follow UAB-13, and removed grants immediately block calls. External processes retain OS-account permissions; annotations are not a sandbox. Rust remains the default maintained runtime; no automatic package installers or model-created server grants. Depends on UAB-04 and UAB-07.

## Shipping gates for every task

- Add or update the catalog/schema, profile availability, instructions, panel controls, permission decisions, audit events, and output limits together. Reject unknown tool arguments and model-supplied identity.
- Exercise a meaningful allow case, denial, malformed/stale input, and relevant interruption/race cases. Use real temporary files and real UI/provider evidence where applicable; fixtures do not establish an integration.
- Preserve traversal/symlink protection, immutable research datasets, explicit deletion approval and trash, and the ban on arbitrary shell. The archaeology project is not a test directory.
- Keep long outputs bounded with continuation cursors. Do not advertise image/document/media support from metadata alone.
- Verify source/package/loaded-build agreement before browser acceptance. Repeat the affected provider matrix; name blocked or unsupported behavior instead of counting it as a pass.
- Run Linux/Intel macOS CI where supported. A physical Intel Mac and the minimum supported macOS/Chrome combination remain separate release checks; do not add architecture-specific or newer-OS dependencies without making that requirement explicit.

The first delivery group is **UAB-01–07**: stable permissions, readiness, bounded grants, durable jobs, provider reliability, controls/reporting and long commands. Next prioritize **UAB-08, UAB-11–14 and UAB-16–18** for useful coding and file workflows. The remaining entries are staged extensions, not commitments to ship every format or application at once.
